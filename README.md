# TCP 延迟代理（慢链路“上传结束收不到回执”复现工具）

带网页的 TCP 延迟代理：可配置目标地址与上下行延迟，网页上直接上传文件试传，
实时显示每条连接的回执、双向字节数与缓冲峰值。用于在本地复现慢链路下
“上传结束却收不到回执”的问题。

内置**维护模式**：值班工程师维护代理前，先在网页上“进入维护”——停收新上传，
等在途上传与回执结束（排空），或宽限期到点后中止剩余连接，之后再恢复接入。

## 快速开始（Docker Compose）

```bash
docker compose up --build
```

* 网页 / API：http://localhost:8000
* TCP 延迟代理监听：`localhost:7000`（可直接对接设备或客户端）
* 示例接收端：容器网络内 `receiver:9000`（先发欢迎行，读到 EOF 后回
  `RECEIPT bytes=<n> sha256=<hex>`）

网页上可修改监听地址/端口、目标地址、上下行延迟（毫秒），保存后对**之后建立
的连接**生效；已建立的连接沿用建立时的配置。修改监听地址/端口会重启监听器。

## 维护模式（值班流程）

网页“维护模式”卡片内操作，也可用 API：

1. **进入维护**：设置宽限期（1～60 秒）后点击“进入维护”。立即生效：
   * 拒绝新 TCP 连接（accept 后直接关闭）与新试传（HTTP 503）；
   * **修改配置不能绕过停收**：维护期间可改延迟等配置，但接入状态保持关闭；
   * 已有连接按建立时的配置继续传输。
2. **等待排空**：卡片实时显示剩余连接数、宽限倒计时、已拒绝的连接/试传计数。
   一条连接要双向传输结束、队列释放、两侧关闭后才算排空（**上行 EOF 不算排空**）。
3. **两种结局**：
   * 全部在途连接正常结束 → 状态“已排空”，逐条结果显示“正常结束”；
   * 宽限期满 → 中止剩余连接（释放其队列），清理完成后才报告“已排空”，
     被中止的连接逐条显示“维护中断”。
4. **恢复接入**：排空后点击“恢复接入”。期限未到也可“取消维护并恢复接入”，
   原连接继续按原配置传输。
5. **轮次隔离**：每轮维护有递增序号（epoch）；上一轮的期限不会再中断连接，
   迟到的结果也不会混入下一轮。

在途的网页试传会关联到具体代理连接（结果里的 `conn_id`）；若该连接被维护
中止，试传返回失败——中止造成的被动 EOF 不会被当作成功回执。

### 浏览器演示（本地接收端）

* **正常排空**：上行/下行延迟设为 2000 ms，开始一个试传，立即进入维护
  （宽限 30 秒）：试传照常完成，维护卡片显示“已排空”，结果为“正常结束”。
* **超时中断**：延迟 2000 ms，开始试传，进入维护（宽限 1～2 秒）：到点后
  连接被中止，试传失败（`maintenance aborted connection #N`），结果显示
  “维护中断”。
* **取消维护**：开始试传，进入维护（宽限 30 秒），随即“取消维护并恢复接入”：
  试传继续完成，新连接立即可接入。

## 关键语义（实现于 `proxy/app/engine.py`）

* **延迟起算**：每个数据块的投递时刻 = 代理读到它的时刻 + 延迟；队列按
  FIFO 投递，连续数据流水通过延迟线，不按读取块数累加等待。
* **64 KiB 应用缓冲**：每方向“已读未写”字节数上限 64 KiB，满则暂停该向
  读取（反向与别的连接不受影响）。
* **半关闭**：收到单向 EOF 后，先把该向待发字节全部写出，再 `write_eof`
  转发半关闭；反向继续传输直到结束。
* **断连释放**：正常结束、对端 RST 或维护中止都会取消泵任务、清空队列、
  关闭两侧连接，并把连接移入历史表。
* **配置快照**：每条连接在 accept 时快照配置，整条连接沿用。
* **维护轮次**：`MaintenanceState` 按 epoch 隔离；看门狗只认当前轮次，
  连接终态（closed/aborted/error）在清理完成后落账并逐条记录。

## 本地开发（不用 Docker）

```bash
pip install -r proxy/requirements.txt
PORT=19000 python3 receiver/server.py &
cd proxy && LISTEN_PORT=17000 TARGET_HOST=127.0.0.1 TARGET_PORT=19000 \
  UP_DELAY_MS=300 DOWN_DELAY_MS=300 \
  uvicorn app.main:app --host 127.0.0.1 --port 18000
```

## 自测

```bash
python3 tests/selftest.py   # 需按上面方式起好接收端与代理（端口见脚本头注释）
```

覆盖：回执字节数/SHA-256 校验、延迟流水化（非按块累加）、64 KiB 缓冲上限
与峰值、EOF 先冲刷再半关闭、连接级配置快照、并发上传、RST 断连释放；
维护模式：正常排空（结果 normal）、停收不可被改配置绕过、新连接/新试传被拒、
超时中止（在途试传关联连接并失败、EOF 不算成功）、取消后旧期限不中断连接、
新一轮不受上一轮迟到结果污染、排空后恢复接入。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/config` | 当前配置、监听状态与接入状态（accepting） |
| POST | `/api/config` | 更新配置（仅影响新连接；维护期间不会恢复接入） |
| GET | `/api/connections` | 活动+历史连接、维护状态：双向字节数、缓冲当前/峰值、回执尾部 |
| POST | `/api/test-upload` | multipart 上传文件，经代理试传并返回回执（维护中 503） |
| POST | `/api/maintenance/start` | 进入维护，body `{"grace_s": 1..60}`；已在维护中返回 409 |
| POST | `/api/maintenance/cancel` | 期限未到取消维护并恢复接入；无进行中维护返回 409 |
| POST | `/api/maintenance/resume` | 排空/取消后恢复接入 |
| POST | `/api/history/clear` | 清空历史连接 |

## 目录结构

```
docker-compose.yml      # proxy + receiver 一键启动
proxy/
  Dockerfile
  requirements.txt
  app/
    main.py             # FastAPI：配置/统计/维护/试传/网页
    engine.py           # 延迟代理引擎（asyncio，无第三方依赖）
    static/index.html   # 网页（含维护模式卡片）
receiver/
  Dockerfile
  server.py             # 示例接收端：欢迎行 + EOF 后回执(字节数+SHA-256)
tests/selftest.py       # 端到端自测（含维护模式场景）
```
